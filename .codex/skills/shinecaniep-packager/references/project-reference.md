## Values To Synchronize

For every release, keep these values consistent:

- `src-tauri/tauri.conf.json`: `productName`, `version`, `identifier`, bundle `copyright`.
- `src-tauri/Cargo.toml`: package `name`, `version`, `description`.
- `src-tauri/Cargo.lock`: root package name/version after Cargo updates it.
- `src-tauri/gen/android/app/build.gradle.kts`: Android `namespace`, `applicationId`, and version from Tauri properties.
- `src-tauri/gen/android/app/src/main/res/values/strings.xml`: `app_name`, `main_activity_title`.
- `dist/config.json`: `systemName`, `systemNameEn`, optional `copyright`.
- `dist/index.html`: `<title>` and default system name; synchronize to root `index.html`.
- `src-tauri/src/lib.rs`: native window title where present.
- `src-tauri/gen/android/app/src/main/assets/tauri.conf.json`: generated asset config after a Tauri build.

## Android Package Rename

When `identifier` changes, update all of the following before building:

- `app/build.gradle.kts` `namespace` and `defaultConfig.applicationId`.
- The source package directory under `app/src/main/java/`.
- Every Java/Kotlin `package` declaration and any generated ProGuard package reference in that source tree.

Do not manually rewrite ignored Gradle `build/` outputs. They are regenerated by the build.

## Build Outputs

- Unsigned universal APK: `src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk`.
- Universal AAB: `src-tauri/gen/android/app/build/outputs/bundle/universalRelease/app-universal-release.aab`.
- Windows release output: `src-tauri/target/release/` and its bundle subdirectories, only when built on Windows.

## Android Signing

The current repository has `shinecaniep-release.jks` and alias `shinecaniep`. Passwords are project secrets and must be supplied at runtime, never copied into this Skill. Locate `zipalign` and `apksigner` under `$ANDROID_HOME/build-tools/<version>` or the local Android SDK fallback. Sign only the exact unsigned APK produced by the current build, and verify with `apksigner verify --verbose --print-certs`.

## Known Build Issue

Tauri plugin builds can fail when these exact cache directories already exist:

- `tauri-plugin-shell-*/android/.tauri/tauri-api`
- `tauri-plugin-fs-*/android/.tauri/tauri-api`

Only after the build reports this exact `File exists` error, remove those narrowly scoped cache directories with user approval and retry once. Do not use a broad Cargo or project cleanup as a first response.

## Verification

For APKs, verify at least:

```bash
aapt dump badging app.apk
apkanalyzer manifest application-id app.apk
apkanalyzer manifest version-name app.apk
apksigner verify --verbose --print-certs app.apk
```

Check that the output contains the confirmed package identifier, application label, version, and the expected signer. For EXEs, verify the expected file exists and report that runtime installation/signature checks were not performed unless a Windows environment is available.
